# 설계 결정: 데이터 파이프라인 운영 방침

> **상태: ✅ 해결됨** — MVP 방침대로 관리자 수동 검수 프로세스로 운영; 이중 파이프라인 없이 예외 처리 방식 채택

## 결정일
2026-05-06

## 질문
TDnet 스크래핑 → XBRL/PDF 파싱 → 관리자 검수 파이프라인이 단일 장애점(SPOF)이 될 수 있습니다. 자동화가 멈추면 데이터 공급이 끊깁니다.

## 결정
**MVP에서는 정상 작동 가정 하에 자동화 중심으로 구축합니다.**

- 별도의 fall-back 수동 입력 우선 구조는 도입하지 않습니다.
- 관리자 수동 입력은 자동 파싱 실패 시 예외 대응 수단으로만 사용합니다.

## 근거
- MVP 단계에서는 검색/주가 추적 대상은 전체 일본 상장주(~3,800개)이나, 배당 데이터는 관리자 검수를 거쳐 점진적으로 확보합니다.
- 초기에는 관리자가 직접 Seed 데이터를 입력하는 방식으로 부트스트랩하며, JPX 종목 마스터는 월 1회 CSV 업로드로 갱신합니다.
- 자동화 장애 발생 시 관리자 수동 입력을 예외 대응 수단으로 사용합니다.
- AI 파싱 비용 제어를 위해 일일 호출 횟수 cap을 두어 예산 초과 시 다음 날 queue에서 자동 재처리됩니다.
