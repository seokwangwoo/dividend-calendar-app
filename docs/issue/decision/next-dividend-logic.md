# 설계 결정: 홈 화면 "다음 배당 예정" 선택 로직

> **상태: ✅ 해결됨** — `get_home_summary()` RPC에서 `expected_payment_date ASC` 정렬로 구현 완료

## 결정일
2026-05-06

## 질문
홈 화면의 "다음 배당 예정" 카드는 보유 종목 중 어떤 기준으로 1개를 선택하여 표시할 것인가?

## 결정
**가장 가까운 배당 1개만 표시하며, 정렬 기준과 동률 처리 규칙을 다음과 같이 적용합니다.**

### 선택 로직

1. **필터링**: 현재월 이후의 `estimated_payment_month`를 가진 배당 이벤트만 대상
2. **정렬 우선순위**:
   - 1순위: `payment_start_date` ASC (확정된 날짜가 있는 것 먼저)
   - 2순위: `estimated_payment_month` ASC
   - 3순위: 세후 금액 DESC (동률 시 더 큰 금액 우선)
3. **계좌 통합**: 같은 종목을 여러 계좌에 보유하면 세후 금액을 합산하여 "KDDI 총 세후 ¥22,500"으로 표시
4. **결과**: 정렬 후 첫 번째 항목 1개만 홈 화면에 표시

### 예시

사용자 보유:
| 종목 | 지급월 | 확정일 | 세후금액 |
|------|--------|--------|----------|
| NTT | 6월 | NULL | ¥8,000 |
| JT | 6월 | 2026-06-30 | ¥15,459 |
| KDDI(NISA) | 6월 | NULL | ¥15,000 |
| KDDI(特定) | 6월 | NULL | ¥7,500 |

정렬 결과:
1. JT (확정일 6/30)
2. KDDI 총 ¥22,500 (지급월 6월, 세후금액 큼)
3. NTT ¥8,000 (지급월 6월)

→ 홈 화면 표시:
```text
다음 배당 예정
┌────────────────────────┐
│ JT                     │
│ 6월 30일 예정           │
│ 세후 ¥15,459            │
│ 상태: 확정              │
└────────────────────────┘
```

### 빈 상태
- 다가오는 배당이 없을 때(예: 12월 말, 남은 배당 없음): 카드를 숨기거나 작은 텍스트로 "예정된 배당 없음" 표시
- 보유 종목 0개인 경우: Empty State와 함께 카드 자체가 표시되지 않음

## 근거
- 사용자가 앱을 열자마자 "가장 가까운 배당은 언제, 얼마인가"를 한눈에 알 수 있어야 합니다.
- 확정된 날짜가 있는 배당을 우선하여 신뢰도를 높입니다.
- 같은 종목을 여러 계좌에 보유핚 경우 총액으로 보여주는 것이 사용자의 "실제 입금액" 기대에 부합합니다.
- 이번 달 전체를 요약하면(B 옵션) 정보 과잉이 되고, 화면이 복잡해집니다.
