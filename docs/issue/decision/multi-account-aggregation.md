# 설계 결정: 동일 종목 다계좌 보유 시 데이터 집계 방식

> **상태: ✅ 해결됨** — 포트폴리오는 계좌별 카드, 홈/캘린더는 종목 단위로 집계하는 RPC 구현 완료

## 결정일
2026-05-06

## 질문
사용자가 같은 종목을 여러 계좌(NISA, 특정口座 등)에 나눠 보유할 때, 포트폴리오/캘린더/홈에서 어떻게 집계하고 표시할 것인가?

## 결정
**계좌별 개별 레코드 유지 + 화면별 다른 집계 방식 적용**

### DB 모델
- `holdings` 테이블은 **계좌별 개별 레코드**를 유지합니다.
- 동일 종목이라도 `account_type`이 다르면 별도 행으로 저장합니다.

### 화면별 집계 규칙
| 화면 | 집계 방식 | 예시 |
|------|----------|------|
| **포트폴리오** | 계좌별 **개별 카드** 표시 | KDDI 100주/NISA 카드, KDDI 50주/특정口座 카드 |
| **홈 (올해 배당)** | 종목 기준 **GROUP BY** 후 세후 금액 합산 | KDDI 총 ¥22,500 |
| **캘린더** | 종목 기준 **GROUP BY** 후 월별 합산 | 6월 KDDI 세후 합계 |
| **종목 상세** | 총 보유 요약 + 계좌별 상세 리스트 | "총 150주 (NISA 100, 특정 50) / 연 세후 ¥22,500" |

## 근거
- 포트폴리오에서는 세금 차이(NISA 면제 vs 특정口座 20.315%)를 명확히 보여주어야 합니다.
- 홈/캘린더에서는 "이번 달/올해 총 얼마"라는 단순한 질문에 답해야 합니다.
- 종목 상세에서는 양쪽 맥락(총합 + 계좌별)을 모두 제공하는 것이 UX상 최선입니다.
