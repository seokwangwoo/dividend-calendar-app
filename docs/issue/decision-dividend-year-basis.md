# 설계 결정: "올해 예상 배당" 집계 기준 — 회계연도 vs 달력연도

> **상태: ✅ 해결됨** — `payment_year` 컬럼 추가 및 사용자 화면은 달력연도 기준으로 통일 완료

## 결정일
2026-05-06

## 질문
홈 화면의 "올해 예상 배당"은 회계연도(`fiscal_year`) 기준으로 집계할 것인가, 달력연도(실제 입금 연도) 기준으로 집계할 것인가?

## 결정
**달력연도(실제 입금 연도) 기준으로 집계하되, `fiscal_year`도 별도 저장하여 관리자 참고용으로 사용합니다.**

### 상세

1. **DB 스키마 변경**
   - `dividend_events` 테이블에 `payment_year` (INTEGER) 컬럼 추가
   - `fiscal_year` (INTEGER)는 유지 — 관리자 화면과 공시 데이터 추적용

2. **집계 기준 변경**
   | 화면 | 집계 기준 |
   |------|----------|
   | 홈 — 올해 예상 배당 | `payment_year = 현재 연도` |
   | 홈 — 이번 달 예상 입금 | `payment_year = 현재 연도 AND estimated_payment_month = 현재 월` |
   | 포트폴리오 — 올해 세후 | `payment_year = 현재 연도` |
   | 캘린더 — 월별 집계 | `payment_year = 선택 연도 AND estimated_payment_month` |
   | 관리자 화면 — 공시 정보 | `fiscal_year` 기준 표시 |

3. **관리자 입력 시**
   - 배당 데이터 입력 시 `estimated_payment_month`와 함께 `payment_year`도 입력
   - 예: FY2026 기말배당, 2026년 6월 지급 예정
     - `fiscal_year = 2026`
     - `payment_year = 2026`
     - `estimated_payment_month = 6`

4. **사용자 화면 레이블**
   - "올해 예상 세후 배당" 그대로 유지 (사용자는 달력연도로 이해)
   - 관리자 화면에서만 "FY2026 기준" 등 회계연도 레이블 표시

### 예시: FY 회계연도와 달력연도의 차이

| 배당 유형 | 회계연도 | 실제 지급월 | `fiscal_year` | `payment_year` |
|-----------|---------|------------|--------------|----------------|
| FY2025 중간배당 | 2025/4~2026/3 | 2025년 12월 | 2025 | 2025 |
| FY2025 기말배당 | 2025/4~2026/3 | 2026년 6월 | 2025 | 2026 |
| FY2026 중간배당 | 2026/4~2027/3 | 2026년 12월 | 2026 | 2026 |
| FY2026 기말배당 | 2026/4~2027/3 | 2027년 6월 | 2026 | 2027 |

만약 `fiscal_year` 기준으로 집계했다면:
- 2026년 6월에 사용자가 앱을 켰을 때, FY2025 기말배당(2026/6 지급)은 `fiscal_year=2025`라서 "올해"에 포함되지 않음 ❌
- 반대로 2025년 12월에 지급된 FY2025 중간배당은 `fiscal_year=2025`라서 포함됨 (이미 지난 돈)

`payment_year` 기준으로 집계하면:
- 2026년에 실제로 입금되는 모든 배당이 "올해"에 포함됨 ✅

## 근거
- 사용자가 이 앱을 켜는 이유는 **"올해 실제로 내 통장에 얼마가 들어오는가"**를 알기 위함입니다.
- 이것은 달력연도 기준입니다. FY2026 기준으로 집계하면 사용자는 "이게 내가 올해 받는 돈이 맞아?"라고 혼란스러워합니다.
- `fiscal_year`는 회계 공시 데이터의 맥락을 유지하기 위해 관리자용으로 분리 보관합니다.
